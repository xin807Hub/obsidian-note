请帮我一次性清理项目中所有过时、废弃、Deprecated 的 API 调用，但不要盲目修改。

工作流程如下：

1. 先全项目扫描过时 API：
   - Java/Kotlin：查找 @Deprecated、编译 warning、IDE 标记、第三方库废弃方法
   - JS/TS/Vue：查找控制台 warning、lint warning、deprecated 类型提示、依赖文档中的替代 API
   - Go：查找 Deprecated 注释、staticcheck 报告，例如 SA1019
   - SQL/配置/脚本中如有废弃参数，也一起列出

2. 输出一份清单，不要立刻修改：
   每一项需要包含：
   
   - 文件路径
   - 行号
   - 当前使用的旧 API
   - 为什么它是过时 API
   - 推荐替代 API
   - 修改风险：低 / 中 / 高
   - 第一步只扫描和输出 deprecated API 清单，不要修改代码。
     等我确认后，再按风险分批修改。
   
3. 分类处理：
   - 低风险：语义完全等价的替换，可以直接修改
   - 中风险：需要保持兼容逻辑，修改后必须补充或调整测试
   - 高风险：涉及业务逻辑、数据结构、认证、安全、并发、数据库行为变化的，不要直接改，先单独列出来说明

4. 修改要求：
   - 保持原有业务行为不变
   - 不要顺手重构无关代码
   - 不要改格式化风格，除非项目已有统一格式化命令
   - 不要升级大版本依赖，除非过时 API 无法在当前版本内替换
   - 每次替换都要优先使用官方推荐的新 API
   - 如果无法确定替代方案，保留 TODO，并写清楚原因，不要猜
   - 低风险和中风险项可以直接修改；高风险项只输出方案，不要动代码。
   
5. 修改完成后执行：
   - 编译命令
   - 单元测试
   - lint / staticcheck / eslint / tsc 等项目已有检查命令
   如果项目中没有明确命令，请先从 README、package.json、Makefile、pom.xml、go.mod、CI 配置中找，不要自己编造命令。

6. 最后输出报告：
   - 已修改的 API 清单
   - 未修改但发现的高风险项
   - 需要我确认的项
   - 执行过的验证命令及结果
   - 是否还有残留 deprecated warning
