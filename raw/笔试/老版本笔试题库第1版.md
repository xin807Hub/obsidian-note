## Java 语言基础知识

### 1. `==` 和 `equals` 的区别是什么？为什么重写 `equals` 时必须重写 `hashCode` 方法？

参考答案：

- `==`：
  对基本类型比较的是值；对引用类型比较的是两个引用是否指向同一个对象。
- `equals`：
  默认继承自 `Object`，默认也是比较引用地址；很多类会重写它，用来比较“内容是否相等”，例如 `String`。
- 为什么重写 `equals` 时必须重写 `hashCode`：
  因为 Java 规范要求，如果两个对象通过 `equals` 判断相等，那么它们的 `hashCode` 必须相同。否则在 `HashMap`、`HashSet` 这类基于哈希的容器中会出现逻辑错误，例如放进去后找不到、去重失效等问题。

### 二、问答题

#### 1. Go 语言 `new` 与 `make` 的作用

参考答案：

- `new(T)`：
  分配一块类型为 `T` 的零值内存，并返回 `*T`
- `make(T, ...)`：
  只用于 `slice`、`map`、`channel`，用于初始化其内部数据结构，返回的是类型本身，不是指针
- 示例：

```go
p := new(int)          // *int
s := make([]int, 10)   // []int
m := make(map[string]int)
ch := make(chan int, 1)
```

#### 2. Go channel 设置缓冲容量与不设置容量的区别？

参考答案：

- 不设置容量：无缓冲 channel，发送和接收必须同时就绪，主要用于协程同步
- 设置容量：有缓冲 channel，只要缓冲区未满就可以先发送，只要缓冲区非空就可以先接收
- 无缓冲更强调同步语义；有缓冲更适合解耦生产和消费速度

#### 3. Go 值接收器与指针接收器区别

参考答案：

- 值接收器会复制接收者，方法内修改不会影响原对象
- 指针接收器接收的是对象地址，方法内可修改原对象内容
- 如果结构体较大，指针接收器可以避免不必要的拷贝
- 指针接收器的方法集和接口实现判断也要特别注意

示例：

```go
type User struct {
	Name string
}

func (u User) SetName1(name string) {
	u.Name = name
}

func (u *User) SetName2(name string) {
	u.Name = name
}
```

#### 4. Go 语言程序是否会发生内存泄露？如果有，泄露的方式有哪些？如果定位？

参考答案：

会。

常见方式：

- goroutine 泄露：
  goroutine 长期阻塞在 channel、锁、网络 IO 上无法退出
- 大切片或子串长期引用底层大对象：
  只用到很小一部分，但整个底层数组仍然被持有
- `time.Ticker`、`time.Timer` 未正确停止或释放
- 全局 `map`、缓存持续增长，没有淘汰策略
- 对象被全局变量、闭包、长生命周期结构意外持有

定位方法：

- 使用 `pprof` 查看堆内存和 goroutine 数量
- 结合 `go tool pprof` 分析热点对象分配和保留路径
- 查看 goroutine profile，定位阻塞位置
- 观察进程内存、goroutine 数、对象数是否持续增长

#### 5. 谈谈 Go 语言垃圾回收机制

参考答案：

- Go 当前 GC 以并发标记清除为主，核心思想是三色标记
- 主要阶段：
  STW 很短暂停顿、并发标记、并发清扫
- 通过写屏障保证并发标记期间对象引用关系的一致性
- Go 的 GC 目标是在控制暂停时间的同时，尽量平衡吞吐和内存占用
- 可以通过 `GOGC` 调整 GC 触发频率

#### 6. 谈谈 Go 语言 GMP 模型

参考答案：

- G：goroutine，用户级协程
- M：machine，对应内核线程
- P：processor，调度上下文，负责把 G 分配给 M 执行
- 一个 M 必须绑定一个 P 才能运行 Go 代码
- P 的数量通常由 `GOMAXPROCS` 控制
- 调度器包含本地队列、全局队列和 work stealing 机制
- 当 goroutine 发生阻塞时，M 可能让出 P，避免影响其它 goroutine 运行

#### 2. Go 语言实现二分查找算法：

参考答案：

```go
func binarySearch(nums []int, target int) int {
	left, right := 0, len(nums)-1
	for left <= right {
		mid := left + (right-left)/2
		if nums[mid] == target {
			return mid
		}
		if nums[mid] < target {
			left = mid + 1
		} else {
			right = mid - 1
		}
	}
	return -1
}
```
