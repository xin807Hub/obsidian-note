### 16. String 处理有哪些常见的性能陷阱？

#### 场景一：`substring` 的内存风险

- Java 6 时代，`substring` 可能共享原字符串底层 `char[]`，小字符串引用会把大数组一起挂住。
- Java 7u6 之后改成复制子串内容，规避了这类内存滞留问题。
- 所以旧版本里，截一小段但长时间持有，可能让大字符串迟迟不能释放。

#### 场景二：敏感词过滤的数据结构选择

- 如果敏感词库很大，不适合反复 `String.replace` 全量扫描。
- 更常见的选择是 Trie 树或 AC 自动机。
- AC 自动机适合多模式匹配，整体效率更稳定。
- `StringBuilder` 适合结果拼装，但不解决“大量词条匹配”的根问题。
