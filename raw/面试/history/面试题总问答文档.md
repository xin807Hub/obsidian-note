## 面试题 2026

### 一、自我介绍与项目总览

#### 1. 自我介绍
- 自我介绍一下。
- 请总结一下自己负责的工作，包括你在项目中承担的角色、对负责模块和整个系统的理解。
- 给不了解系统的人介绍下你做的产品 / 系统是什么，解决什么问题，核心架构是怎样的。

#### 2. 项目背景与职责
- 讲讲这个 AI 项目。
- 讲讲 AI 视频解析平台出于什么目的做的。
- 你在实习中主要做了哪些工作？
- 有没有记忆比较深的方案设计案例？讲讲你是怎么设计的。

### 二、AI 视频解析平台与链路设计

#### 3. 平台能力与输出
- 最大视频文件大小限制是多少？
- 最终解析内容以什么形式输出给用户？
- 提取音频并调用大模型处理的整个链路是什么？

#### 4. 去重、分片与存储
- 如何利用 MD5 配合分布式锁做内容级别去重？
- 为什么要在 `SETNX` 的基础上再配合 Lua 脚本实现分布式锁？
- Redis 的分片状态是怎么设计的？
- 分片续传的具体实现逻辑是什么？
- 分片大小定为 5MB 的依据是什么？
- 分片上传是串行还是并行？配置了几个线程？
- MinIO 里未合并成功的残余分片文件，怎么处理？

#### 5. AI 提效与 AICR
- 你平常怎么使用 AI？
- AI 怎么帮你们提效？
- 如果候选人回答“我一般用 AI 写前端、后端代码，我负责测试和管控”，可以继续追问：通常让 AI 写哪类代码、提示词怎么组织、生成后重点检查什么、AI 写错过什么、并发事务权限幂等这类高风险逻辑是否还会直接交给 AI。
- AICR 的交互流程是怎么样的？
- AICR 帮助你们检测出什么问题？有没有具体例子？
- AICR 的提示词是怎么写的？
- 短期记忆的滑动窗口是多大，怎么定义的？
- 长期记忆是怎么设计的？
- 了解 OpenClaw 吗？它也有长期记忆，这两者的区别是什么？
- 请分享一下你的 AI 相关实践，包括你对 AI 的使用、好用的工具 / 方法，以及如何用 AI 达到更好的效果？

### 三、高并发、缓存、MQ 与分布式一致性

#### 6. 营销与库存场景
- 电商系统里如何防止超卖？
- 超卖怎么保障数据的最终一致性？
- 你说的库存这块其实就是乐观锁，对吧？当初这么设计是考虑性能优化吗？
- 你提到的优惠券规则引擎是什么？
- 延迟队列处理超时订单时，怎么通过乐观锁解决支付关单冲突？
- 你是怎么解决单用户优惠券超领问题的？
- 你是怎么解决高并发下优惠券库存超发为负数的问题的？
- 高并发场景下，用乐观锁方案会不会有性能问题？为什么？如果并发量继续上涨，如何优化？

#### 7. 异步化与发券可靠性
- 注册发券逻辑从同步改成异步后，怎么保证券成功发放？
- 分布式链路异步化改造的背景是什么？为什么要做？你是怎么落地的？
- 异步化改造后，系统扩展性与容错能力主要体现在哪些方面？
- 失败重试 / MQ 重试会不会导致多发券？你怎么保证不重发、不多发券？
- 达到最大重试次数依然失败，有什么兜底策略？
- 异步重度依赖 MQ，如果消息积压或消费者消费不过来，怎么监控和处理？
- RabbitMQ 怎么实现消息不丢失和不重复消费？
- 如果候选人只说“MQ 用过”，可以继续追问：为什么引入 MQ、如何保证消息不丢失、重复消费怎么处理、积压怎么定位、失败重试和死信怎么设计。

#### 8. Redis、锁与缓存
- Redis 和分布式锁如何设计数据结构？
- Redis 缓存击穿具体用了哪种方案？为什么选择逻辑过期？
- Redis 持久化是怎么配置的？
- 用 Lua 脚本保证扣库存的原子性，若脚本执行到一半 Redis 节点挂了会怎样？
- Redis 的基础数据类型有哪些？
- Redis 的 ZSET 是如何实现通过 member 快速查找分数的？底层数据结构是什么？
- 查询用户“最近上传的 10 个视频”，选 Redis 的哪种数据结构，为什么？
- Redisson 看门狗在业务耗时一直续期的情况下，锁还能释放吗？
- 如果候选人只说“了解 Redis”，可以继续追问：常用数据类型怎么选、缓存击穿穿透雪崩怎么处理、持久化怎么配、分布式锁有什么风险、为什么 ZSET 能同时支持排序和按 member 查找。

#### 9. 系统瓶颈与可用性
- 假设视频平台流量突增 10 倍，你觉得瓶颈会在哪个组件？
- 调 API 时若突然宕机，业务端如何给前端做用户感知？
- 你在项目中有没有遇到过性能瓶颈，或者做过压测与性能优化实践？具体场景、问题和解决方式是什么？
- 有没有做过性能优化或方案层面的考虑？
- 如果候选人只说“做过优化”，可以继续追问：优化前瓶颈怎么定位、看了哪些指标、做了哪些动作、结果提升了多少、有没有副作用或权衡。
- 如果候选人说“做过高并发优化”，可以继续追问：瓶颈是在数据库、缓存、锁、线程池还是下游接口；你做的是削峰、限流、异步化、分片还是缓存前移；最终怎么保证一致性和可恢复性。

### 四、Java 基础、并发与 JVM

#### 10. Java 基础
- Java 的泛型了解吗？
- Java 泛型如何“解除”或绕过泛型限制？
- 如果面试者只回答“了解”，可以继续追问：泛型解决了什么问题、为什么叫伪泛型、什么是类型擦除、为什么不能 `new T()`、`? extends` 和 `? super` 的区别是什么？
- Java 的反射呢？
- Java 中数组和列表之间怎么相互转化？
- JDK 1.8 中的 Stream 流有过接触吗？
- Java 中 `finally` 里直接 `return` 会怎样？
- 线程和进程的区别是什么？
- 协程了解吗？或者 Java 的虚拟线程是怎么实现的？

#### 11. 并发与集合
- 并发场景下直接用 HashMap 有什么线程安全问题？
- 用到本地线程池了吗？核心参数是怎么评估设置的？
- 讲一下 Java 里 Map 的实现，主要是 HashMap 的底层结构。
- HashMap 的扩容流程是怎样的？新版本对 rehash 做了什么优化？
- 如果候选人只说“HashMap 底层是数组加链表”，可以继续追问：Java 8 为什么引入红黑树、什么时候树化、为什么容量通常是 2 的幂、扩容时元素怎么迁移、并发下为什么不能直接用 HashMap。
- 如果候选人说“线程池用过”，可以继续追问：任务是 CPU 密集还是 IO 密集、核心线程数怎么算、队列为什么这么设、拒绝策略怎么选、线上如何判断线程池是否配置合理。

#### 12. JVM
- 讲一下 JVM 内存模型，内存里有哪几个部分？
- 如何查看 Java 进程的内存使用情况？
- 类加载的过程是怎样的？有几个步骤？
- Java 是怎么进行垃圾回收的？
- JVM 的垃圾回收算法有哪些？它们的区别、优缺点是什么？
- 有没有实践或调优过 JVM？
- 如果候选人只说“了解 JVM”或“看过垃圾回收”，可以继续追问：运行时数据区有哪些、对象怎么判断可回收、常见 GC 算法区别、CMS / G1 的理解、排查过哪些 GC 或内存问题。

## AI 后端开发面试题

说明：
- 面向 AI Agent、AI 平台、智能体后端、模型编排方向。
- 题目按“主问题 + 可继续追问”整理，方便面试前自查。
- 项目细节题必须替换成真实信息，尤其是并发量、耗时、成本、模型选择和失败率。

### 一、实习与项目拷打

#### 1. 实习拷打
- 自我介绍一下，重点讲你做的 AI 后端 / Agent 相关工作。
- 你在团队里的角色是什么，负责哪些模块？
- 你做的项目解决什么问题，给业务带来了什么价值？
- 你最有成就感的一次优化是什么？优化前后的指标是什么？
- 实习里你做过最难的一件事是什么？难点在技术还是业务理解？
- 如果让你重新做一次这个项目，你最想改哪一块？

#### 2. 项目拷打
- 讲讲你们的 AI 项目 / Agent 平台整体目标和典型使用场景。
- 从用户发起请求到结果返回，完整链路是怎样的？
- 哪些环节是同步返回，哪些环节必须异步化？为什么？
- 你亲自负责的核心模块有哪些？不要泛讲整个平台。
- 你们怎么衡量这个系统做得好不好？看成功率、时延、成本还是效果？
- 如果用户问题很复杂，系统会怎么拆解任务？
- 如果一次任务执行失败，怎么给用户反馈？怎么支持重试和恢复？

### 二、Agent 流程与架构设计

#### 3. 任务编排与状态流转
- 状态机是用于干什么的？
- 你们的任务状态一般有哪些？为什么不能只用一个“进行中”？
- 状态机如何保证任务可恢复、可重试、可观测？
- 多步骤任务里，如何处理部分成功、部分失败？
- 如果一个步骤执行超时，你们怎么判定是失败、重试还是人工介入？
- 状态流转如何防止并发更新冲突？

#### 4. 规划、执行与追问
- 在流程中，AI 是否会再次询问用户？
- 在规划中，AI 是否会进一步细化动作？
- 你们为什么需要 Planner / Executor / Replanner 这样的拆分？
- 什么情况下由模型自由规划，什么情况下走固定工作流？
- 如果模型规划出的步骤不合理，后端怎么兜底？
- 一个复杂任务能不能并行执行多个子任务？如何合并结果？

#### 5. 工具调用与结果回收
- 模型决定调用工具后，后端具体做了哪些事情？
- 工具调用失败时，怎么做超时、重试、熔断和降级？
- 一个工具返回结果过大时，怎么裁剪上下文，避免把窗口打爆？
- 如何防止模型反复调用同一个工具造成死循环？
- 工具返回不可信数据时，后端如何做校验和清洗？
- 工具执行和最终回复之间，怎么做结构化中间态保存？

### 三、框架与技术选型

#### 6. 框架与语言
- 你们使用的是什么框架？为什么选它？
- 整体技术栈是 Python 还是 Java？为什么这样分工？

- 如果让你从 0 到 1 设计一套 AI 后端，你会先拆哪些核心模块？
- 你们做过哪些框架层面的抽象，避免模型或工具提供方强绑定？

#### 7. 外部方案参考

- 你们自研和开源框架的边界是怎么划分的？
- 如果要替换底层模型或工具协议，需要改动多大？

### 四、记忆与上下文管理

#### 8. 记忆设计

#### 9. 上下文窗口与压缩
- 你们怎么控制上下文长度？
- 历史对话太长时，是截断、摘要还是分层压缩？
- 如何避免摘要把关键信息压没？
- 多轮任务里，当前计划、执行结果、用户原始目标分别怎么保留？
- 不同角色提示词、工具结果、记忆内容混在一起时，怎么做上下文分层？

#### Q1：如果服务端支持“请求取消”接口，前端如何配合？
前端在发起新请求时先发送取消信号（或取消 token），并在本地同时 `abort()`，做到“客户端不再消费 + 服务端停止计算”。

#### 16. String 处理有哪些常见的性能陷阱？

##### 场景一：`substring` 的内存风险

- Java 6 时代，`substring` 可能共享原字符串底层 `char[]`，小字符串引用会把大数组一起挂住。
- Java 7u6 之后改成复制子串内容，规避了这类内存滞留问题。
- 所以旧版本里，截一小段但长时间持有，可能让大字符串迟迟不能释放。

##### 场景二：敏感词过滤的数据结构选择

- 如果敏感词库很大，不适合反复 `String.replace` 全量扫描。
- 更常见的选择是 Trie 树或 AC 自动机。
- AC 自动机适合多模式匹配，整体效率更稳定。
- `StringBuilder` 适合结果拼装，但不解决“大量词条匹配”的根问题。
