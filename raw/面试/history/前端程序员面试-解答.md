# 前端程序员面试参考解答

## 1. 大屏中包含大量 ECharts 图表或动画，如何避免卡顿？

### 参考答案
核心思路是“四件事”：按需渲染、减少计算、减少重绘、做好降级。

1. 按需渲染
- 图表进入可视区再初始化（Intersection Observer）。
- 隐藏页签或不可见模块暂停更新。

2. 控制渲染开销
- 关闭或弱化非必要动画：`animation: false` 或缩短动画时长。
- 降低高频交互触发频率（tooltip、mousemove 走节流）。
- 高频更新用 `setOption(option, { notMerge: false, lazyUpdate: true })`，避免整图重建。

3. 数据与线程优化
- 多图共享同一数据拉取结果，统一分发，避免重复请求。
- 复杂聚合放到 Web Worker，避免阻塞主线程。

4. 生命周期与兜底
- 组件卸载时 `chart.dispose()`，避免内存泄漏。
- 建立 FPS 监控，低帧率时自动关闭动画/降采样。

## 2. 大屏数据来自多个接口，如何管理异步请求与失败重试？

### 参考答案
建议用“数据服务层 + 调度器 + 缓存 + 重试”。

1. 统一数据源配置
```ts
interface DataSource {
  id: string;
  url: string;
  method?: 'GET' | 'POST';
  params?: Record<string, unknown>;
  interval?: number;
  retry?: { max: number; baseDelay: number };
}
```

2. 调度策略
- 启动时注册所有数据源，按 `interval` 轮询或走 WebSocket。
- 相同 `url + params` 短时间内请求合并。
- 成功后统一写入 store，组件只订阅 store。

3. 重试与降级
- 失败按指数退避重试（1s/2s/4s...）。
- 达到上限后保留上次成功数据并展示“数据延迟/异常”状态。
- 用 `AbortController` 取消过期请求，防止脏数据覆盖。

## 3. 客户要求多主题切换（白天/夜间），怎么实现？

### 参考答案
用“CSS 变量 + 图表主题 + 全局状态持久化”。

1. CSS 变量
```css
:root {
  --bg-color: #ffffff;
  --text-color: #222;
  --primary: #1677ff;
}
[data-theme="dark"] {
  --bg-color: #0f172a;
  --text-color: #e2e8f0;
  --primary: #3b82f6;
}
```

2. 全局切换
- store 维护 `currentTheme`。
- 根节点挂 `data-theme`。
- 写入 `localStorage`，刷新后恢复。

3. ECharts 同步
- 预注册主题：`echarts.registerTheme('dark', themeObj)`。
- 切换后重建或统一刷新 option，保证颜色/坐标轴一致。

## 4. 大屏 i18n 如何覆盖 ECharts label/tooltip 文本并统一管理？

### 参考答案
原则是“配置模板化，渲染时翻译注入”。

1. 文案模板化
- 配置里不写死中文，写 key：`titleKey: 'sales.title'`。
- 或模板：`"{{t('sales.title')}}"`。

2. 渲染前递归翻译
- 在图表初始化前，对 option 做深度遍历，把 key 解析成目标语言。

3. 语言切换处理
- 语言切换时重新生成完整 option 再 `setOption`。
- 避免在 formatter 闭包里长期持有旧语言 `t`。

## 5. 你当时遇到的最大挑战是什么？

### 参考答案
最大挑战是“多图联动下的数据一致性和性能冲突”。

- 现象：用户快速筛选时 8 张图会并发请求，出现结果覆盖和卡顿。
- 定位：请求竞态 + 主线程频繁重绘。
- 方案：统一状态源（Pinia）+ 请求取消（AbortController）+ 合并更新批次。
- 结果：交互延迟明显下降，联动结果一致性问题消失。

面试建议：按 STAR（场景-任务-行动-结果）结构回答。

## 6. 如果现在重做，你会改进哪些地方？

### 参考答案
1. 前后端契约前置
- 明确时间轴粒度、空值语义、时区规则，减少反复对齐成本。

2. 可观测性前置
- 为接口耗时、图表渲染耗时、FPS 建立监控面板，提前发现瓶颈。

3. 渐进式性能策略
- 默认采样 + 异步细节加载，先保证流畅再补精度。

4. 工程化改进
- 图表配置 schema 校验、组件自动化回归测试、统一错误降级组件。

## 7. 说下前端防抖、节流的原理、实现、应用场景

### 参考答案
1. 原理
- 防抖（debounce）：触发后等待 N ms，N ms 内再次触发就重新计时。
- 节流（throttle）：每 N ms 最多执行一次。

2. 实现
```ts
export function debounce<T extends (...args: any[]) => void>(fn: T, wait = 300) {
  let timer: ReturnType<typeof setTimeout> | null = null;
  return (...args: Parameters<T>) => {
    if (timer) clearTimeout(timer);
    timer = setTimeout(() => fn(...args), wait);
  };
}

export function throttle<T extends (...args: any[]) => void>(fn: T, wait = 300) {
  let last = 0;
  return (...args: Parameters<T>) => {
    const now = Date.now();
    if (now - last >= wait) {
      last = now;
      fn(...args);
    }
  };
}
```

3. 场景
- 防抖：搜索输入、窗口 resize、表单校验。
- 节流：滚动监听、拖拽、mousemove、图表 hover 联动。

## 8. 搜索防抖下出现请求乱序（后发先至）怎么办？

### 参考答案
这是竞态条件（Race Condition）。常见两种解法：

1. AbortController 取消旧请求（推荐）
```ts
let controller: AbortController | null = null;

async function search(keyword: string) {
  if (controller) controller.abort();
  controller = new AbortController();
  const res = await fetch(`/api/search?q=${keyword}`, { signal: controller.signal });
  const data = await res.json();
  renderResults(data);
}
```

2. 版本号兜底
```ts
let version = 0;

async function search(keyword: string) {
  const v = ++version;
  const res = await fetch(`/api/search?q=${keyword}`);
  const data = await res.json();
  if (v === version) renderResults(data);
}
```

## 9. 点击趋势图一个点后，如何联动 7~8 个图表刷新？

### 参考答案
1. 单一事实源
- 把“当前时间点/筛选条件”放到 Pinia，不在组件间互调。

2. 事件驱动
- 主图 `click` 只做一件事：更新全局筛选条件。
- 其余图表订阅条件变化后自行请求和重绘。

3. 请求治理
- 请求层做防抖、去重、取消，避免请求风暴。
- 所有图带请求版本，防止旧响应覆盖。

4. 体验优化
- 联动批量更新（Promise.allSettled + 一次性 commit）。
- 部分图失败时局部降级，不阻塞整体。

## 10. 后端数据缺失很多时间点，如何让趋势图“满点展示”？

### 参考答案
1. 先补时间轴
- 按粒度生成完整时间桶（如 1h 按分钟生成 60 点）。

2. 再做值补全
- 计数类缺失补 0。
- 状态类可前值延续（forward fill）。
- 无法推断可补 `null`，前端显示断线。

3. 前后端分工
- 后端负责“完整时间轴 + 对齐”。
- 前端负责视觉策略（断点、平滑、空值样式）。

## 11. 趋势图 10 万点卡顿，Downsampling 放后端还是前端？

### 参考答案
结论：主策略放后端，前端做轻量兜底。

- 后端降采样降低传输体积和前端渲染压力，可复用到多端。
- 前端可再按当前像素宽度做二次抽稀。
- 常用算法：LTTB（保留峰谷和趋势转折）。

LTTB 口述：保留首尾点，把中间点分桶，每桶选择三角形面积最大的点。

## 12. 实时流式数据下切换 1h/24h，如何减少 UI 跳动？

### 参考答案
1. 双缓冲
- BufferA 当前显示，BufferB 预加载目标窗口。
- BufferB 准备好后原子切换，避免先清空再重绘。

2. 快照 + 增量
- HTTP 拉历史快照，WebSocket 收实时增量。
- 合并时按时间戳去重，冲突按序列号或更新时间决议。

3. 稳定策略
- 固定不同时间窗的采样粒度（1h=1min，24h=5min）。
- 降低动画，减少视觉抖动。

## 13. Pinia vs Vuex：核心优势、场景、大型项目 store 组织

### 参考答案
1. 对比
- Pinia 更轻量，API 简洁，TypeScript 推断更自然。
- Vuex 传统模式需要 `mutation` 样板，心智负担更重。

2. Pinia 核心优势
- 组合式写法更贴合 Vue 3。
- 按业务域拆 store 更自然，热更新与调试体验更好。

3. 适用场景
- Vue 3 中大型项目优先 Pinia。
- 老项目可“新模块先 Pinia、旧模块渐进迁移”。

4. 大型项目组织建议
- 按领域拆分：`useAuthStore`、`useDashboardStore`、`useAssetStore`。
- store 只放共享状态和业务动作，UI 临时状态留组件。
- 跨 store 通过 action 调用，避免循环依赖。

## 14. 面试官常见追问（含简答）

### Q1：如果服务端支持“请求取消”接口，前端如何配合？
前端在发起新请求时先发送取消信号（或取消 token），并在本地同时 `abort()`，做到“客户端不再消费 + 服务端停止计算”。

### Q2：除了取消请求，怎么保证结果顺序正确？
使用版本号/时间戳机制，响应返回后只允许“最新版本”更新 UI。

### Q3：React 中怎么清理未完成请求？
在 `useEffect` 中创建 `AbortController`，并在 cleanup 中执行 `controller.abort()`。

### Q4：ECharts / AntV 如何处理大数据？
核心是降采样、分层渲染、增量更新和动画控制；工程上通常配合后端聚合一起做。

### Q5：你做过多大数据量趋势图？
建议按真实项目回答：数据规模、机器配置、瓶颈位置、优化前后指标（首屏时延、交互延时、FPS）。
