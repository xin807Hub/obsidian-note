# AI后端开发面试题

说明：
- 面向 AI Agent、AI 平台、智能体后端、模型编排方向。
- 题目按“主问题 + 可继续追问”整理，方便面试前自查。
- 项目细节题必须替换成真实信息，尤其是并发量、耗时、成本、模型选择和失败率。

## 一、实习与项目拷打

### 1. 实习拷打
- 自我介绍一下，重点讲你做的 AI 后端 / Agent 相关工作。
- 你在团队里的角色是什么，负责哪些模块？
- 你做的项目解决什么问题，给业务带来了什么价值？
- 你最有成就感的一次优化是什么？优化前后的指标是什么？
- 实习里你做过最难的一件事是什么？难点在技术还是业务理解？
- 如果让你重新做一次这个项目，你最想改哪一块？

### 2. 项目拷打
- 讲讲你们的 AI 项目 / Agent 平台整体目标和典型使用场景。
- 从用户发起请求到结果返回，完整链路是怎样的？
- 哪些环节是同步返回，哪些环节必须异步化？为什么？
- 你亲自负责的核心模块有哪些？不要泛讲整个平台。
- 你们怎么衡量这个系统做得好不好？看成功率、时延、成本还是效果？
- 如果用户问题很复杂，系统会怎么拆解任务？
- 如果一次任务执行失败，怎么给用户反馈？怎么支持重试和恢复？

## 二、Agent 流程与架构设计

### 3. 任务编排与状态流转
- 状态机是用于干什么的？
- 你们的任务状态一般有哪些？为什么不能只用一个“进行中”？
- 状态机如何保证任务可恢复、可重试、可观测？
- 多步骤任务里，如何处理部分成功、部分失败？
- 如果一个步骤执行超时，你们怎么判定是失败、重试还是人工介入？
- 状态流转如何防止并发更新冲突？

### 4. 规划、执行与追问
- 在流程中，AI 是否会再次询问用户？
- 在规划中，AI 是否会进一步细化动作？
- 你们为什么需要 Planner / Executor / Replanner 这样的拆分？
- 什么情况下由模型自由规划，什么情况下走固定工作流？
- 如果模型规划出的步骤不合理，后端怎么兜底？
- 一个复杂任务能不能并行执行多个子任务？如何合并结果？

### 5. 工具调用与结果回收
- 模型决定调用工具后，后端具体做了哪些事情？
- 工具调用失败时，怎么做超时、重试、熔断和降级？
- 一个工具返回结果过大时，怎么裁剪上下文，避免把窗口打爆？
- 如何防止模型反复调用同一个工具造成死循环？
- 工具返回不可信数据时，后端如何做校验和清洗？
- 工具执行和最终回复之间，怎么做结构化中间态保存？

## 三、框架与技术选型

### 6. 框架与语言
- 你们使用的是什么框架？为什么选它？
- 整体技术栈是 Python 还是 Java？为什么这样分工？
- 模型编排层、业务服务层、任务调度层分别用什么实现？
- 为什么没有完全照搬现成 Agent 框架，而是做了自定义封装？
- 如果让你从 0 到 1 设计一套 AI 后端，你会先拆哪些核心模块？
- 你们做过哪些框架层面的抽象，避免模型或工具提供方强绑定？

### 7. 外部方案参考
- 你们参考过 Claude Code 吗？
- 如果参考过，你们借鉴了哪些设计，而不是只学了表面交互？
- 你怎么看待“现成框架很快能跑，但难以落生产”的问题？
- 你们自研和开源框架的边界是怎么划分的？
- 如果要替换底层模型或工具协议，需要改动多大？

## 四、记忆与上下文管理

### 8. 记忆设计
- 对于记忆管理，你们有什么想法？
- 短期记忆和长期记忆分别存什么？
- 记忆是在什么时候写入的？每轮对话都写吗？
- 如何判断一段信息值得长期保留，而不是污染记忆？
- 长期记忆是向量化存储、结构化存储，还是两者结合？
- 记忆召回时如何控制相关性，避免把不相关历史拉进来？

### 9. 上下文窗口与压缩
- 你们怎么控制上下文长度？
- 历史对话太长时，是截断、摘要还是分层压缩？
- 如何避免摘要把关键信息压没？
- 多轮任务里，当前计划、执行结果、用户原始目标分别怎么保留？
- 不同角色提示词、工具结果、记忆内容混在一起时，怎么做上下文分层？

## 五、Skill、Tool 与 MCP

### 10. Skill 与工具抽象
- 你有没有想过 Skill、MCP 这些？
- 你对 Skill 有什么了解？
- 你理解的 Skill 更像 Prompt 模板、工作流模板，还是能力插件？
- 一个 Skill 最少应该包含哪些信息？
- Skill 之间如何复用，如何避免 prompt 和逻辑散落在代码里？
- 什么时候该做 Skill，什么时候直接写死在业务流程里？

### 11. MCP 与协议设计
- 你怎么理解 MCP？
- MCP 和普通 HTTP API / 函数调用有什么区别？
- 如果把内部能力接成 MCP Server，最核心的收益是什么？
- MCP 适合暴露哪些能力，不适合暴露哪些能力？
- 资源、工具、提示词这几类能力你怎么区分？
- 如果一个 MCP Server 不稳定，Agent 侧怎么做超时、重试和降级？
- MCP 接入后，如何做认证、鉴权、审计和租户隔离？

## 六、模型、Prompt 与效果控制

### 12. Prompt 编排
- 你们的系统提示词一般怎么拆？哪些是全局的，哪些是任务级的？
- 如何把业务约束、安全规则和输出格式稳定传给模型？
- 你们会要求模型输出 JSON / DSL 吗？怎么提升可解析性？
- 如果模型输出格式不稳定，后端怎么兜底？
- 你如何理解“提示词工程”和“确定性后处理”的边界？

### 13. 模型选型与效果评估
- 为什么选择当前模型？看哪些指标？
- 不同任务会不会选不同模型？比如规划、检索总结、代码生成、审核。
- 你们怎么做效果评估？线上和离线指标分别看什么？
- 幻觉、漏答、乱调用工具这几类问题分别怎么治理？
- 成本和效果冲突时，你们怎么做权衡？
- 如果用户追问“为什么这次回答不如上次”，你会怎么排查？

## 七、后端工程化与稳定性

### 14. 异步任务与可靠性
- 任务队列是怎么设计的？
- 如何保证任务幂等？
- 如何避免同一个用户请求被重复消费？
- 延迟任务、死信队列、补偿机制分别在什么场景下用？
- 长任务如何断点续跑？
- 任务执行记录要存到什么粒度，才能支持排障和回放？

### 15. 可观测性与故障排查
- 你们监控哪些核心指标？
- 一次请求跨模型、跨工具、跨队列时，链路追踪怎么做？
- 如何区分是模型问题、工具问题，还是业务代码问题？
- 线上最常见的故障有哪些？你们怎么快速定位？
- 如果用户说“AI 卡住了”，你第一反应看哪些日志和指标？
- 对于高成本工具或模型调用，如何做审计和费用归因？

### 16. 安全、权限与生产落地
- 工具调用如何做权限控制？
- 不同用户、不同租户的上下文和记忆如何隔离？
- 如何避免 prompt injection、越权读数据、误调用危险工具？
- 文件上传、网页抓取、代码执行这类高风险能力怎么上生产？
- 如果模型产生了高风险动作建议，系统如何增加人工确认环节？
- 你觉得 AI 后端和传统后端相比，最大的新增风险是什么？

## 八、常见追问与反问准备

### 17. 面试官常见深挖
- 你负责的到底是“调 API”还是“做平台能力”？
- 你们为什么需要状态机，而不是普通接口串起来就行？
- 你们怎么证明系统不是靠 prompt 硬凑，而是工程化可维护的？
- 记忆、规划、工具调用里，哪一块最容易出线上事故？为什么？
- 如果现在让你把系统迁到另一套模型提供方，最痛的点是什么？

### 18. 你可以反问面试官
- 你们现在 AI 后端更偏 Agent 编排、RAG 平台，还是模型服务治理？
- 线上最关注的是效果、稳定性还是成本？
- 团队现在是偏框架建设，还是偏业务落地和交付？
- 对这个岗位来说，更希望候选人补强哪一块：工程化、模型理解还是业务抽象？
