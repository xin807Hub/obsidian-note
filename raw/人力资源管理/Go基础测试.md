# 一、Slice（切片）

### 1️⃣ slice 底层结构

**答案**
slice 本质是一个结构体：

```go
type slice struct {
    ptr *T   // 指向底层数组
    len int
    cap int
}
```

- `ptr`：底层数组起始地址
- `len`：当前可访问长度
- `cap`：从 ptr 开始到底层数组末尾的容量

【必须命中】三要素
【加分】能说出 slice 只是“视图”，不是数组

------

### 2️⃣ len 和 cap 不同的场景

```go
s := make([]int, 2, 5)
```

- `len = 2`
- `cap = 5`

【必须命中】make 的第二、第三个参数含义

------

### 3️⃣ 代码输出

```go
s := []int{1, 2, 3}
a := s[:1]
b := s[1:2]
a[0] = 100
fmt.Println(s)
```

**输出**

```text
[100 2 3]
```

【必须命中】共享底层数组
【踩雷】说“a 和 s 没关系”

## 二、append 陷阱

### 4️⃣ append 什么时候扩容

- 当 `len+1 > cap` 时
- 扩容规则：
  - 小 slice：≈2 倍
  - 大 slice：增长比例逐步降低（实现细节）

【必须命中】可能触发重新分配数组

------

### 5️⃣ append 覆盖问题

```go
s := []int{1, 2, 3}
a := append(s, 4)
b := append(s, 5)
fmt.Println(a, b)
```

**可能输出**

```text
[1 2 3 5] [1 2 3 5]
```

原因：

- `s` 还有 cap
- `a` 和 `b` 共用底层数组
- 后一次 append 覆盖前一次

【必须命中】“共享底层数组”
【踩雷】认为一定输出不同结果

------

### 6️⃣ 为什么提前分配 cap

```go
dst := make([]T, 0, len(src))
```

- 减少扩容
- 提升性能
- 保证 append 不污染 src

【必须命中】性能 + 安全

------

### 7️⃣ 函数中 append 的可见性

- 不扩容：修改会反映到外部
- 发生扩容：外部不可见

【必须命中】是否发生扩容决定行为

------

### 8️⃣ 如何保证不修改原 slice

```go
dst := append([]T(nil), src...)
```

或

```go
dst := make([]T, len(src))
copy(dst, src)
```

【必须命中】copy 或新 slice

------

# 三、for 循环

### 9️⃣ for-range 变量复用

- **循环变量是复用的**
- 每次迭代都会被覆盖

【必须命中】不是新变量

------

### 🔟 map 遍历

```go
for k, v := range m
```

- 顺序不保证
- 每次运行可能不同

【必须命中】map 是 hash 表

------

### 1️⃣1️⃣ for + 指针陷阱

```go
var arr []*int
for i := 0; i < 3; i++ {
    arr = append(arr, &i)
}
```

**结果**
`arr` 中三个指针指向同一个 `i`

【必须命中】`i` 地址复用

**正确写法**

```go
for i := 0; i < 3; i++ {
    v := i
    arr = append(arr, &v)
}
```

或

```go
arr = append(arr, new(int))
*arr[len(arr)-1] = i
```

## 四、for + goroutine

### 1️⃣2️⃣ 输出结果

```go
for i := 0; i < 3; i++ {
    go func() {
        fmt.Println(i)
    }()
}
```

**常见输出**

```text
3 3 3
```

原因：
goroutine 执行时 `i` 已经变成 3

【必须命中】闭包 + 变量复用

------

### 1️⃣3️⃣ 正确写法

```go
for i := 0; i < 3; i++ {
    i := i
    go func() {
        fmt.Println(i)
    }()
}
```

或

```go
for i := 0; i < 3; i++ {
    go func(x int) {
        fmt.Println(x)
    }(i)
}
```

## 五、并发 + slice / map

### 1️⃣4️⃣ 并发 append slice

- **数据竞争**
- 可能 panic
- 可能数据丢失

【必须命中】slice 非并发安全

------

### 1️⃣5️⃣ 并发写 slice 方案

- `sync.Mutex`
- `channel` 串行写
- 分片 slice + 合并

【加分】提到 `sync.Pool` 或批量合并

------

### 1️⃣6️⃣ map 并发

- 原生 map 非并发安全
- 并发写会 panic

------

### 1️⃣7️⃣ sync.Map 适用场景

适合：

- 读多写少
- key 稳定
- 高并发读

不适合：

- 频繁写
- 强类型需求

## 六、逃逸分析

### 1️⃣8️⃣ 什么是逃逸

- 变量生命周期超出栈
- 被分配到堆

【必须命中】“生命周期”而不是“return”

------

### 1️⃣9️⃣ slice 返回是否逃逸

```go
func f() []int {
    s := make([]int, 0, 10)
    return s
}
```

**结论**
`s` 的 **底层数组会逃逸**

【加分】能说 `-gcflags=-m`

------

### 2️⃣0️⃣ 如何判断逃逸

```bash
go build -gcflags="-m"
```
