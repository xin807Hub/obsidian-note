# ClickHouse 排序键优化 - 性能测试方案

## 测试目标
验证 `ods_traffic_records_local`（优化前）与 `ods_traffic_records_local_new`（优化后）的性能差异

## 测试环境
- 数据库: TK_DB_SP@192.168.6.211
- 端口: 8123(HTTP), 9000(Native)
- 账户: default/Ck@2o20...
- 测试表:
  - ods_traffic_records_local (原始排序键)
  - ods_traffic_records_local_new (小时粒度排序键)

## 测试场景设计

### 1. 基准查询测试 (Scenario 1)
模拟原截图中的查询 - 时间范围 + msisdn 精确匹配
```sql
SELECT count(*)
FROM {table}
WHERE start_time >= '2026-03-20 00:00:00'
  AND start_time < '2026-03-31 00:00:00'
  AND msisdn = '381641449273'
```

### 2. 多字段组合过滤 (Scenario 2)
测试复合条件过滤性能
```sql
SELECT count(*), sum(up_bytes), sum(down_bytes)
FROM {table}
WHERE start_time >= ? AND start_time < ?
  AND msisdn = ?
  AND app_type = ?
```

### 3. 小时粒度查询 (Scenario 3)
验证优化后排序键对小时粒度查询的优势
```sql
SELECT toStartOfHour(start_time) as hour, count(*), sum(up_bytes)
FROM {table}
WHERE toStartOfHour(start_time) = ?
  AND msisdn = ?
GROUP BY hour
```

### 4. 多 msisdn IN 查询 (Scenario 4)
测试多值匹配性能
```sql
SELECT msisdn, count(*)
FROM {table}
WHERE start_time >= ? AND start_time < ?
  AND msisdn IN (?, ?, ?, ?, ?)
GROUP BY msisdn
```

### 5. 聚合查询 (Scenario 5)
测试分组聚合性能
```sql
SELECT app_type, app_id, count(*) as cnt, sum(up_bytes) as up, sum(down_bytes) as down
FROM {table}
WHERE start_time >= ? AND start_time < ?
  AND msisdn = ?
GROUP BY app_type, app_id
ORDER BY cnt DESC
LIMIT 10
```

### 6. 数据分布采样 (Scenario 6)
随机采样测试数据获取真实 msisdn 值用于测试

## 采集指标
- query_duration_ms: 查询耗时
- read_rows: 读取行数
- read_bytes: 读取字节数
- result_rows: 结果行数
- result_bytes: 结果字节数
- memory_usage: 内存使用

## 测试方法
1. 每个场景执行 3 次取平均值
2. 冷/热缓存分别测试
3. 记录 EXPLAIN 执行计划

## 预期结果
优化后表应该：
- read_rows 显著减少（预期 10-100 倍）
- query_duration_ms 大幅降低
- 相同查询条件下性能提升 50-100 倍
