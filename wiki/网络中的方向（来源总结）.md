# 网络中的方向（来源总结）

## 来源信息

- 原文：[raw/业务核心/网络中的方向.pdf](../raw/%E4%B8%9A%E5%8A%A1%E6%A0%B8%E5%BF%83/%E7%BD%91%E7%BB%9C%E4%B8%AD%E7%9A%84%E6%96%B9%E5%90%91.pdf)
- 主题：在 DPI / XDR 场景下区分“方向”的不同语义，避免把 [[业务方向]]、[[链路方向]] 和 [[流方向]] 混为一谈

## 核心结论

讨论“方向”之前，必须先对齐观察视角。原文强调至少存在两种常见视角：

- 以网络边界为参照讨论的 [[链路方向]]
- 以应用访问关系为参照讨论的 [[业务方向]]

在当前 DPI 代码框架中，建流方式是“按上行业务方向建流”，因此日常说的 [[流方向]] 默认更接近业务语义；但移动统一 DPI 规范中的 XDR “方向”字段，要求体现的是链路语义，而不是业务语义。

这意味着：系统实现上虽然可以按 [[业务方向]] 建流，但在流节点或结果字段里仍然要补充表达 [[链路方向]]，否则会把产品内部实现语义和对外规范语义混在一起。

## 关键概念提炼

### 1. [[业务方向]]

描述的是“谁访问谁”的业务关系，通常可理解为客户端到服务端、请求方到被访问方的方向。

### 2. [[链路方向]]

描述的是数据相对网络边界的流入或流出，例如省网内到省网外、IDC 内到 IDC 外。

### 3. [[流方向]]

在本文语境下，流方向是 DPI 内部建流时采用的默认方向语义。由于当前实现按上行业务方向建流，所以它默认贴近 [[业务方向]]。

### 4. [[出访与入访]]

“出访”“入访”不是纯粹的单一方向概念，而是把 [[业务方向]] 与 [[链路方向]] 叠加后的复合表达。

### 5. [[DPI]]

本文所有讨论都落在 DPI 产品语境下。方向字段的解释、建流策略以及 XDR 字段填充，都要结合具体网络边界来理解。

## 字段语义速记

原文给出的字段说明可以归纳为几个稳定判断：

- `USER_IP` 表示网内侧地址，例如省网出口场景填写省网内 IP，IDC 出口场景填写 IDC 内 IP
- `App Server IP` 表示网外侧地址，例如省网外 IP 或 IDC 外 IP
- `UL Data` / `DL Data` 按网络边界定义上下行，强调的是 [[链路方向]] 上的流入流出
- `ServerLocation` 用来补充说明真正服务器位于网内还是网外，避免单靠 `USER_IP` / `Server_IP` 误判角色

更适合直接记忆的口径见：[[方向判断速查表]]

## 实现启示

原文对实现层的提醒可以概括为：

1. 先明确当前讨论的是业务语义还是网络边界语义
2. 允许系统内部按 [[业务方向]] 建流，以便统一会话组织方式
3. 但在流节点、统计字段和 XDR 输出时，必须显式保留 [[链路方向]]
4. 对“[[出访与入访]]”这类混合术语，要拆开看其背后的业务与链路含义
