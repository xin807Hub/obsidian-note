# 方向判断速查表

## 一句话总结

不同场景下“方向”的最核心区别，不在于名字，而在于参照物不同：

- [[业务方向]]：参照物是访问双方，回答“谁访问谁”
- [[链路方向]]：参照物是网络边界，回答“流量是进还是出”
- [[流方向]]：参照物是系统建流规则，回答“这条流在系统里怎么组织”
- [[出访与入访]]：是 [[业务方向]] 和 [[链路方向]] 混合后的复合表达

## 方向判断口诀

1. 先问参照物是谁
2. 如果看客户端和服务端，就是 [[业务方向]]
3. 如果看省网 / IDC / 企业边界，就是 [[链路方向]]
4. 如果看流表、会话、建流规则，就是 [[流方向]]
5. 如果说“出访 / 入访”，一定继续追问它拆开后的业务语义和链路语义

## 不同场景下最核心的区别

| 场景 | 关注点 | 最核心的问题 | 对应概念 |
| --- | --- | --- | --- |
| 业务分析 | 访问关系 | 谁主动访问谁 | [[业务方向]] |
| 网络边界统计 | 流量进出 | 相对网内 / 网外是流入还是流出 | [[链路方向]] |
| DPI 内部实现 | 会话组织 | 这条流按什么方向建流 | [[流方向]] |
| 产品口径 / 规范字段 | 对外表达 | 最终输出字段要求表达哪种方向语义 | 通常要区分 [[业务方向]] 与 [[链路方向]] |
| 出访 / 入访判定 | 混合判断 | 业务关系和边界关系组合后叫什么 | [[出访与入访]] |

## 上下行的取值怎么取

这里最容易错。本文语境里的上下行，默认按 [[链路方向]] 取值，不按“客户端上传 / 下载”的直觉取值。

### 省网出口 DPI

- `UL Data`：从省网内流出到省网外的流量
- `DL Data`：从省网外流入到省网内的流量

### IDC 出口 DPI

- `UL Data`：从 IDC 内部流出到 IDC 外部的流量
- `DL Data`：从 IDC 外部流入到 IDC 内部的流量

### 通用记法

- `UL` = 网内 -> 网外
- `DL` = 网外 -> 网内

所以 `UL` / `DL` 的判断基准不是“谁是客户端”，而是“谁在边界内、谁在边界外”。

## `UL Data` / `DL Data` 的统计口径

《[[网络中的方向（来源总结）]]》里还给了流量值本身怎么累计的规则：

- 对场景一，按内层 IP 包头开始计算的数据包大小总和
- 对其他场景，按链路层封装开始计算的数据包大小总和
- 对特定业务 XDR，填写整个合成单据的总上行流量或总下行流量

也就是说，`UL` / `DL` 不只是方向标签，还对应各自方向上的累计字节数。

## 实际使用时的稳妥顺序

1. 先确定边界在哪里，例如省网边界、IDC 边界、企业边界
2. 再判断某个报文是网内流出还是网外流入，得到 [[链路方向]]
3. 再判断谁访问谁，得到 [[业务方向]]
4. 最后才决定这条记录应该怎么标成“上行 / 下行”或“出访 / 入访”
